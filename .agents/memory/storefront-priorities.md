name: Storefront game priorities
description: The owner's intended emphasis for the homepage's post-hero card browsing area.
---

Keep the card browsing area immediately after the hero Riftbound-only. Pokémon remains elsewhere on the site, but not as a choice in this showcase.

**Why:** The user first requested a Riftbound focus, then explicitly asked “Pokemon kısmını kaldırabilirsin şuan oradan”. This supersedes the earlier mixed-game tabs in this section.

**How to apply:** Keep actual card-detail navigation accessible by mouse, keyboard and touch, and do not let carousel gestures consume ordinary clicks. This is not permission to replace Pokémon's provider or catalog or remove its other homepage sections.

Match this showcase to the site's existing colors rather than introducing an unrelated gold/green palette. Use the actual Riftbound icon instead of a sparkle symbol. Short headings, subtitles and labels should start each word uppercase using Turkish casing and use proper punctuation.

**Why:** The user rejected the previous look as “çok ai” and not matching the site, explicitly corrected the lowercase second words in headings/subtitles, and requested a Riftbound icon instead of the perceived AI icon.

**How to apply:** Preserve source card names as printed. Apply the casing to authored showcase copy, including subtitle text, without adding decorative template-like messaging.

Use the owner's supplied desktop and mobile artwork as the hero and header design direction, with real catalog cards in place of the reference's illustrated cards.

**Why:** The user explicitly requested “Tam bu heroyu ve headerı istiyorum” and supplied a clean portal-and-rocks background, transparent Turkish ribbon and mobile reference. This supersedes earlier full-width centered desktop heading and text-clipped flag requests.

**How to apply:** Desktop copy belongs left and cards right. Header and hero together fill the first viewport. Keep copy, controls and branding compact without reducing the card fan. Mobile follows the stacked reference, with real navigation, legible spacing and both game logos clear of the fixed bottom menu. Use the supplied red ribbon for “Türkiye'de”, not a tiled flag texture. Do not apply the hero's gold accents to the separate post-hero showcase.

The owner requested a YouTube cinematic as the hero background instead of the static landscape. Use the original GoCards logo on both desktop and mobile, not a recreated brand mark.

**Why:** The owner supplied the video, requested smaller copy and unchanged desktop cards, then explicitly asked for the old logo back and a mobile layout matching their supplied reference with large cards.

**How to apply:** Play silently and loop with captions disabled, respect reduced-motion preferences and retain the supplied landscape when playback is unavailable. YouTube can return a bot-verification screen in preview, so reveal its frame only after confirmed playback. Mobile copy precedes the large card fan, followed by actions, trust items and game logos.

Fit mobile content to the actual space remaining between the header and fixed bottom navigation, not just the viewport dimensions.

**Why:** Preview banners can consume additional space, so a layout that fits an equally sized direct screenshot can still hide the game logos inside the user's preview.

**How to apply:** Base compact fallbacks on the hero's measured available height and preserve a small gap above the bottom navigation.

Keep a non-dismissible scrolling information bar above the menu on desktop and mobile.

**Why:** The owner explicitly requested a permanent bar with “500 TL üzeri ücretsiz kargo” and other shopping information. This supersedes the earlier request to hide the shipping announcement on mobile.

**How to apply:** Keep the strip in the sticky header, support reduced motion and include its height in hero layout calculations. Do not hide it on the homepage or restore a dismiss button.
